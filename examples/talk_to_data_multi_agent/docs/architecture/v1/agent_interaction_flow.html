TRACCIA RUNTIME

How the agents interact

Each specialist receives a typed result from the previous stage. Language models never execute SQL or analytical code directly; deterministic boundaries perform those operations.
1

Router agent

Understands the question, resolves semantic names, classifies the analytical method, and asks only essential questions.

Produces
AnalyticsIntent
2

Planner agent

Tests data sufficiency, selects one approved analytical tool, and creates no more than three independent query tasks.

Produces
AnalyticsPlanQueryTask[]
3

SQL agents

Run concurrently for independent tasks. Each sees the semantic layer and retrieved schema evidence.

Produces
SQLGeneration[]
4

Execution + analysis

A deterministic SQL guard and read-only executor run first. The selected application plugin then computes the analysis.

Produces
QueryResult[]AnalysisOutcome
5

Insight agent

Turns evidence into executive language while retaining method, assumptions, warnings, sources, and confidence.

Produces
InsightReport
6

Verifier

Approves or conservatively corrects unsupported claims.

Produces
Review

Clarification branch

The router pauses the persisted conversation. The next human message resumes with the same correlation ID, up to the configured limit.

Bounded refusal branch

Missing data, undefined metrics, unsafe SQL, or an unavailable causal model produces an explicit blocked result rather than an invented answer.

Completed branch

The dashboard receives typed text, SQL, table, chart, notice, citations, follow-ups, agent run IDs, and semantic-version metadata.

Semantic layerMetrics, dimensions, joins, synonyms, certification, digest
Schema RAGpgvector hybrid retrieval and evidence IDs
RuntimeBudgets, retries, cancellation, state, provider routing
GovernancePolicy, Traccia/OpenTelemetry, immutable audit events
Trace hierarchy: one conversation turn shares a workflow/correlation ID. Router starts the chain; planner references the router run; SQL runs reference the planner; insight references the last query run; verifier references the insight run.
