Executive experience

A full conversational canvas supports free-flow questions, minimum necessary clarification, reconnectable progress, tables, charts, SQL where permitted, downloads, assumptions and suggested drill-downs.

Airline agent team

Configured router, sufficiency, SQL, insight and verifier agents use different model tiers. Their prompts, semantic references and repair rules are airline application assets, not hard-coded Runtime behavior.

Traccia Runtime services

Conversation APIs, semantic graph planning, schema-validated DAG execution, scoped cache, PostgreSQL checkpoints and leases, governance, model/method registries, verification, evaluation, OpenTelemetry and Traccia export are reusable across domains.

Airline analytical intelligence

The versioned semantic layer and method plugins define airline metrics, dimensions, joins, thresholds, descriptive calculations and scenario limitations. Predictive claims require a validated analytical model, not another LLM prompt.

Customer data and models

The customer publishes governed read-only marts, schema/catalog knowledge, stable keys, freshness/completeness evidence and approved forecast, causal, simulation or optimization endpoints. Database grants and RLS are the final access boundary.

Assurance path

Every result carries semantic digest, query fingerprint, source and column lineage, method/model versions and upstream result IDs. Verification checks claims against cells; evaluation gates changes against golden questions before promotion.

Hard boundary: Traccia Runtime does not own airline formulas, warehouse transformations, customer data, business thresholds, or predictive models. It provides the contracts and controls that make those components composable, bounded, durable and auditable.
