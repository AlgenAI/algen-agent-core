Performance and cache plane
Scope policyEach namespace independently selects global, tenant, user, session or run isolation. Authorization fingerprints can further partition entries.
Capability and retrieval cacheProvider capabilities are globally shared; schema retrieval is tenant-scoped and avoids repeated embedding and vector-search work.
Read-only query cacheUser-scoped SQL results use short TTLs, data-version material and bounded payloads. Writes and side effects never enter this path.
Model and tool cacheExact non-streaming model responses and idempotent read tools are user-scoped. Streaming, raw responses and side-effecting tools bypass caching.
Stampede protectionConcurrent identical misses share one in-flight loader. Local LRU bounds memory while Redis supports multiple processes and replicas.
Secure invalidationOpaque hashed or HMAC keys, TTL, size limits, version tags, fail-open errors, and explicit tag invalidation protect correctness and privacy.

Separation of responsibility: the customer data platform owns ingestion and curated marts; the airline application owns semantics and analytical methods; Traccia Runtime owns contracts, orchestration, safety, durability and traceability.
Clarify or block: material ambiguity pauses the conversation. Missing data, an uncertified metric, an invalid plan, or an unavailable model produces a bounded explanation—not a fabricated answer.
Action boundary: analytical recommendations remain advisory. Any operational action uses a separately authorized side-effecting tool and a persisted approval checkpoint.
Cache boundary: cache scope follows the narrowest authorization boundary. Freshness and safety outrank hit rate; writes, destructive tools and raw provider payloads are never cached.
